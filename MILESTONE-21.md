# Workstream A — the contractility effector

## A1. The mechanism as modelled

One new ODE state, `ino_mult`: a dimensionless multiplier on both
ventricles' maximal elastance (S1's `E` — the systolic span only;
the diastolic curve is not an elastance-maximum property). The
reflex computes a target from the same normalised MAP error
signal the HR, resistance and venomotor effectors use:

```
target = 1 + swing x clamp(gain x err, -1, 1)
d(ino)/dt = (target - ino) / tau_h
```

— the same first-order form as S13's own elastance ODE (S25):
`dE_lv,max/dt = (-E_lv,max + alpha_Elv * ns + gamma_Elv) / tau_h`.
The state is integrated by the same fixed-order RK4 at the same
substep and folded into the per-tick FNV trace hash after the
refill state, like every other state. Determinism re-verified
(§A4). Measured state trajectory (shipped configuration):

| Condition | `ino_mult` |
|---|---|
| Resting, reflex on (post window) | 0.9944 (quiet at the operating point) |
| −750 mL, bleed end | 1.1997 (at the cited +20% ceiling) |
| −750 mL, post window | 1.1283 |
| −1,500 mL, bleed end and post | 1.2000 (saturated throughout) |
| +1,000 mL infusion, post window | 0.9034 (symmetric down-swing engaged) |

The Ursino-lineage source already on file (S13, Scarsoglio &
Ridolfi's Frontiers supplementary model description) was re-read

(S25), Table S7 (baroreceptor parameters) and Table S1 (initial
conditions) — and the values below are transcribed from that
reading. S13's locator in `parameters.json` is extended to say so.

| Parameter | Value | Status | Source / basis |
|---|---|---|---|
| `contractility_tau_seconds` | 3.0 s | **cited** | S13 Table S7, tau_h — the heart effector's time constant (arterial 12 s, venous 60 s). The fast sympathetic limb |
| `contractility_swing_fraction` | 0.20 | **cited** | S13 (S25) with Tables S1/S7: LV steady-state target `E = alpha_Elv * ns + gamma_Elv = 1.0 * ns + 2.0` mmHg/mL passes through the resting `Elv,max,0 = 2.5` mmHg/mL (Table S1) at resting ns = 0.5 and reaches 3.0 / 2.0 at ns = 1 / 0 — a ±20% swing. RV: `0.46 * ns + 0.92` about `Erv,max,0 = 1.15` is the identical ±20% fraction, so one shared multiplier state is faithful to both effectors |

Adoption discipline is Milestone 18's exactly: the cited
quantities are the swing fraction and the time constant; the
engine does not adopt S13's absolute elastances (its own are
S1's: LV 2.8, RV 0.8 mmHg/mL), its sigmoid, or its
sympathetic-activity state.

# Workstream B — per-layer opacity in both shells

## B1. What was built

**Native shell** (`native/src/render.rs`): `ShadeUniforms`
carries `opacity` (the former pad slot; the pick uniforms are a
separate struct, untouched). A third shade pipeline —
`shade_translucent_pipeline` — shares the shader with alpha
blending enabled and depth write off (depth *testing* stays
on). `SceneState` gains an `opacity` map (layer key → opacity,
absent = 1.0). `draw_shaded` now draws the opaque group first
(opacity 1, the Milestone-16 path unchanged), then the
translucent group in manifest order — the manifest lists layers
innermost-first with the integumentary shell last, so outer
translucent layers composite over inner ones. View mode gains
the `G` key (glass shell: integumentary opacity 0.15 ↔ opaque).

**Web shell** (`web/viewer.js`): `FS_SHADE` gains `uOpacity`,
written as the fragment alpha. `draw()` partitions exactly like
the native shell: opaque layers first (no state changes), then
translucent layers under `gl.BLEND` (SRC_ALPHA,
ONE_MINUS_SRC_ALPHA) with `depthMask(false)`, after which
depth mask and blending are restored so the pick pass and the
next frame see the defaults. Every layer row in the sidebar
gains an opacity slider (10–100%) read by `layerOpacity()`, and
two presets are generated in `boot()`: **glass shell** (all
layers on, integumentary 15% — the native shell's verified
focus state) and **reset layers**. `web/index.html` is
untouched.

## B2. Picking cannot be corrupted by opacity — the proof

By construction: in both shells the id pass is a *separate*
pipeline/shader with its own uniforms, and it never reads the
opacity state. Opacity lives only in the shaded pass. Evidence,
per shell:

- **Native, pixel level** (the real id pass, llvmpipe): the
  foreground probes were run in the glass focus state (shell at
  0.15) and in the opaque states at the same pixels. Forehead:
  glass → integumentary slot 0 (skin), identical to the
  all-layers opaque probe. Heart-centre: glass → integumentary
  slot 0, identical to the all-layers opaque probe. The
  Milestone-16 probes are also unchanged (forehead skeletal+muscular
  → frontal bone; thigh → right vastus medialis; heart-centre
  cardiovascular+nervous → cardiovascular slot 629, right
  ventricle). The verify harness asserts the glass/opaque
  equality as a hard check: **PASS**.
- **Web, data level**: `pick()` and `FS_PICK` are byte-untouched
  by this milestone, so the Milestone-7-FIX codec cannot have
  regressed: verify_web W6 still executes the shipped encoder +
  decoder over **all 1,545 slots, 0 failures** (miss pixel and
  unknown bit → null). New W8 additionally asserts the shipped
  `pick()` source contains no reference to opacity, blending or
  depth masking at all. **Rendered-pixel web picking remains
  unexercised — no browser exists on this VM** (the standing
  Milestone 6/7 limitation, unchanged).

## B3. The translucency proof (native, llvmpipe)

New verify frame `front_cv_nervous_glass`: all layers, focus =
cardiovascular + nervous (dim 0.78, as Milestone 16),
integumentary opacity 0.15. The harness measures both focus
frames with ratio-family pixel counts (channel ratios survive
dimming, so a pixel's source family is identifiable through

- **Heart region** — skin-dominated fraction of lit pixels

  In the Milestone-16 frame essentially every lit pixel in the
  heart's projected region was skin; in the glass frame, none

- **Brain region** — nervous-ratio pixels (yellow family):
  opaque focus **22** → glass shell **101**.

cardiovascular-ratio pixels above a brightness floor — read

the composite sits between the two families' ratios and below
any floor calibrated on undimmed colours; the measurement was
wrong, not the render (the frame below shows the interior
plainly). The shipped gate measures the defect itself — shell
dominance — instead.

## B4. Known limitations of the implementation

- Sorting is **per-layer** (manifest order), not per-fragment:
  overlapping translucent layers composite in layer order, and
  a translucent layer's own front and back faces both blend
  (depth write is off in the translucent group), so a shell
  reads slightly deeper where both faces overlap a pixel. No
  per-fragment sorting is attempted; documented, not hidden.
- Wireframe overlay on a translucent layer is drawn with the
  wire pipeline (unblended dark lines), as before.
- The web shell's rendered pixels remain unverified on this VM
  (no browser); its proof is the executed-code and data-level
  chain (W1–W8) plus the native shell's pixel-level proof over
  the same packs and the same design.
